# Планувальник

Десктопний планувальник дня. Побудований навколо одного дня: погодинний
розклад, задачі на день (без часу) та нотатки — три окремі сутності,
плюс бічна панель з наступними/попередніми днями відносно сьогодні.

Стек: **Tauri 2 + React + TypeScript + Tailwind CSS + Supabase**
(Postgres + автентифікація). Дані тепер зберігаються в хмарі — доступ
до одного й того ж розкладу можливий з кількох пристроїв (десктоп,
а згодом і телефон) під одним акаунтом. Інтернет потрібен завжди —
локального офлайн-режиму немає (свідомий вибір заради простоти).

## Крок 1 — створіть проєкт Supabase (безкоштовно)

1. Зареєструйтесь на https://supabase.com і натисніть **New project**.
2. Дайте проєкту будь-яку назву, задайте пароль бази даних (збережіть
   його на всякий випадок, хоча в коді він не використовується), оберіть
   регіон (найближчий до вас) і натисніть **Create new project**.
   Створення займає десь хвилину.
3. У лівому меню відкрийте **SQL Editor** → **New query**, вставте туди
   весь вміст файлу `supabase/schema.sql` з цього проєкту і натисніть
   **Run**. Це створить усі таблиці й налаштує захист даних (RLS) —
   кожен користувач бачитиме тільки свої записи.
4. У лівому меню відкрийте **Project Settings** → **API**. Скопіюйте:
   - **Project URL** (виглядає як `https://xxxxx.supabase.co`)
   - **anon public** ключ (довгий рядок під "Project API keys")

## Крок 2 — підключіть застосунок до вашого проєкту

У корені проєкту (поряд з `package.json`) створіть файл `.env`
(скопіюйте `.env.example` і перейменуйте) і вставте туди свої значення:

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=ваш-anon-public-ключ
```

Файл `.env` не потрапляє в git (він вже в `.gitignore`) — це ваш
приватний ключ доступу до вашої ж бази.

## Крок 3 — встановлення й запуск

Все як і раніше потребує Node.js та Rust — дивіться нижче.

```bash
npm install
npm run tauri dev
```

При першому запуску застосунок покаже екран входу. Натисніть
"Немає акаунту? Зареєструватись", введіть пошту й пароль. Supabase
надішле лист із підтвердженням на пошту (перевірте й Спам) —
підтвердіть і після цього можна входити.

## Що потрібно встановити перед першим запуском

1. **Node.js** 18+ — https://nodejs.org
2. **Rust** — https://www.rust-lang.org/tools/install
3. Системні залежності Tauri для вашої ОС —
   https://tauri.app/start/prerequisites/

## Збірка готового інсталятора

```bash
npm run tauri build
```

Готовий файл з'явиться в `src-tauri/target/release/bundle/`.

## Іконка програми

Тимчасова іконка лежить у `src-tauri/icons/icon-source-1024.png`.
Замініть її на свою 1024×1024 PNG і виконайте:

```bash
npm run tauri icon src-tauri/icons/icon-source-1024.png
```

## Структура проєкту

```
src/
  components/       — усі UI-компоненти
  hooks/            — useDayData (дані одного дня), useWeekSummaries (тиждень)
  db/database.ts    — весь доступ до Supabase (заміна колишнього SQLite-шару)
  lib/supabaseClient.ts — клієнт Supabase, читає ключі з .env
  lib/session.ts    — тримає id поточного залогіненого користувача
  lib/date.ts        — робота з датами українською
  types.ts          — сутності: ScheduledTask, DailyTask, DayNote, MultiDayNote
supabase/schema.sql — SQL-схема для Supabase (виконати один раз, крок 1.3)
src-tauri/          — Rust-обгортка Tauri (вікно)
```

## Мобільна версія (наступний крок)

Оскільки дані тепер у хмарі, а не в локальному SQLite-файлі, той самий
React-код можна зібрати під Android/iOS через `tauri android init` /
`tauri ios init` — застосунок одразу підключиться до того ж Supabase-
проєкту й покаже той самий розклад. Для Android потрібен Android Studio,
для iOS — Mac з Xcode. Скажіть, коли будете готові — розберемо це
окремим кроком, бо там свої нюанси з інтерфейсом під дотик.
